## probe_cdb.py — Ansys APDL Command Block Database Format

### Format Specification (from Ansys APDL Command Reference)

The .cdb file is a fixed-width ASCII text format:

| Column | Content |
|--------|---------|
| 1      | Line type: space = data, '*' = command, '/' = command, '#' = comment |
| 2–70   | Data fields (fixed-width, column-aligned) |
| 71     | Continuation flag: 'C' = next line continues this record |

### Key Record Types

#### NBLOCK (Node Block)
  Defines nodes with their coordinates.
  Format: NODE, NNUM, X, Y, Z, SECP, CS, TEMP, SCYLY, SCZLY, NMATE, NSEC, NPT
  - NNUM: node number (integer)
  - X, Y, Z: coordinates in model units (mm)
  - SECP: section parameter (optional)
  - CS: coordinate system number

#### EBLOCK (Element Block)
  Defines elements with node connectivity.
  Format: ELTYPE, ELSEC, ELReal, ELMAT, ELREF, ENUM, N1, N2, N3, N4, N5, N6, N7, N8
  - ELTYPE: element type number (references ET definition)
  - ELSEC: section number (references SECTYPE)
  - ELMAT: material number
  - ENUM: element number
  - N1–N8: node connectivity (up to 8 nodes for solid/brick elements)

#### ET (Element Type)
  Defines element type properties.
  Format: ET, ETYPE, ELEM, REAL, KEYOPT, CONST1..8
  - ETYPE: element type number
  - ELEM: element name (e.g., SHELL281, SOLID185)
  - KEYOPT: key options (bitmask)

#### SECTYPE (Section Type)
  Defines section type for layered composite shells.
  Format: SECTYPE, ID, TYPE, NAME, LABEL
  - ID: section number
  - TYPE: section type (SHELL, BEAM, SOLID, etc.)
  - NAME: user-defined name

#### SECDATA (Section Data)
  Defines section parameters, including layer stack.
  Format: SECDATA, PAR1, PAR2, ...
  For SHELL sections with layered composites:
  - LAYER: number of layers
  - ANG, THICK, MAT, INTEGR: per-layer angle, thickness, material, integration points

#### CMBLOCK (Component Block)
  Defines named components (sets of nodes, elements, etc.).
  Format: CNAME, CNUM, CTYPE, CNAME2, LABEL
  - CNAME: component name
  - CNUM: component number
  - CTYPE: component type (NODE, ELEM, KEYP, etc.)

#### Units Declaration
  The header block declares units:
  /UNITS,1 (1 = mm-tonne-s, 2 = m-kg-s, etc.)

### Example Minimal .cdb File

  /PRE7
  ET,1,SHELL281
  SECTYPE,1,SHELL,COMPOSITE
  SECDATA,2,0,2.0,1,5
  CMBLOCK,BODY-OML,ELEM
  NBLOCK,1,0.0,0.0,0.0
  NBLOCK,2,10.0,0.0,0.0
  EBLOCK,1,1,1,1,1,1,1,2

### Gmsh .msh → .cdb Relationship

Gmsh generates .msh files with nodes and elements. The P13 writer
must convert Gmsh output to .cdb format:
- Gmsh node tags → NBLOCK node numbers
- Gmsh element node arrays → EBLOCK connectivity
- Gmsh physical groups → CMBLOCK named components
- Material/layer info → SECTYPE/SECDATA

### Key Design Decisions for P13 Writer

1. Use text mode (not binary) — .cdb is ASCII
2. Fixed-width column formatting (70 chars + continuation)
3. Node numbers and element numbers must be unique integers
4. Element connectivity references NBLOCK node numbers
5. SECTYPE/SECDATA must match the layer stack from materials DB
6. CMBLOCK names must follow §5 naming contract
7. Header must declare mm–tonne–s units (F8)
